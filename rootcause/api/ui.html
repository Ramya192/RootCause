Causal decision intelligence

From “what happened?” to “what would happen if we acted?”

Dashboards and prediction models show what is associated with an outcome. RootCause goes further: it learns the causal structure of a domain, estimates what each lever really moves, and ranks interventions by return and fairness, saying how far to trust each answer.

The idea

Why correlation is not enough

A lender charges higher rates to riskier borrowers, so loans with high rates default more. Is the rate causing defaults, or is risk causing both? Predictive models cannot tell; a causal model is built to.

What RootCause models

What it adds on top

It adjusts for the shared causes, then tries to break its own answer: a shuffled-lever noise check, and how strong a hidden confounder would have to be to erase the effect. Where the data are observational, results are labelled associations, not proven causes.

A real finding

Same loans, different outcome definition, different answer

Freddie Mac mortgages originated in 2019. “Seriously delinquent” (90+ days late) looks like credit risk, but most of those 2019 delinquencies were COVID forbearance: borrowers who paused payments with relief and later caught up. About 92% of them were relief-flagged and 0.5% ended in liquidation. Excluding relief-flagged loans changes what the pipeline concludes.

What the 2019 “defaults” actually were

92.4% relief-flagged (forbearance, deferral, assistance plan)7.6%
Of the 2,473 seriously delinquent loans in the 2019 sample, 97.4% later returned to current and 0.5% were ever liquidated. For comparison, 47% of 2007's delinquent loans were liquidated. Source: Freddie Mac loan performance files, aggregates only.
Does it work?

How it is checked, including where it falls short

Against a known answer

Simulated data with a planted graph and effects. Over 10 fresh draws: edge precision 0.97, recall 0.93, exact graph in 8 of 10; effect error 0.007; top intervention correct 10/10. The simulated Freddie Mac twin recovered the planted rate effect to about 13%.

Against a real experiment

On the Illinois workplace wellness randomized trial (4,834 employees), the pipeline's adjusted estimate (+0.0020) sat inside the trial's confidence interval, its noise check correctly failed, and it reproduced the trial's sex-subgroup estimates (women −0.031, men +0.046).

Where it does not work

LiNGAM drops to 0.51 edge precision once a binary outcome is included, so PC stays the default. The robustness value cannot detect confounding. Causal anomaly detection is no better than a Mahalanobis baseline at spotting swapped values. On real data there is no ground truth, so those estimates stay associations.

What this project demonstrates

Skills and depth

Causal inference

  • Backdoor adjustment with refutation (DoWhy)
  • T/S/X/R/doubly-robust learners (CausalML)
  • Cinelli–Hazlett sensitivity, cross-checked against PySensemakr

Causal discovery

  • PC, GES and DirectLiNGAM, benchmarked
  • Domain priors as required / forbidden edges
  • Stress tests: small n, non-Gaussian, nonlinear

Evaluation rigour

  • Truth-scored simulations, true ATE by simulating do()
  • Real-trial benchmark; bootstrap stability
  • Negative results written up, not hidden

LLM and agents

  • CrewAI hierarchical crew (7 agents + manager)
  • AutoGen analyst → skeptic → writer
  • Programmatic grounding check on every number

Data and ML engineering

  • Feast offline/online feature store
  • Multimodal ingestion (PDF, image, CNN/ViT)
  • Five real and simulated domains from one config format

Software engineering

  • FastAPI service with async job queue
  • Docker image and GitHub Actions CI
  • 490 tests; bugs found by CI fixed with regression tests
On real, non-experimental data (credit, claims, mortgages) the numbers are associations adjusted for measured factors, not proven causes: lenders and insurers set terms based on risk, so unmeasured confounding is expected. The pipeline labels these results as such, and its checks show how sensitive they are.
